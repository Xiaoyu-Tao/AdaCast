Define a time-series forecasting task. Collects mandatory dataset/modeling parameters, optional task notes including user-supplied or synthesized `adjustment_skill_priors` with possibly missing numeric values or explicit read-only file references, an optional unified `window_stride` (default `1`, with `stride` accepted as an input alias), and one chronological split strategy: either `train_ratio` + `val_ratio` + `test_ratio`, or exactly two timestamp boundaries, `train_end_timestamp` and `validation_end_timestamp`. `window_stride` controls the sliding-window step used consistently for training, adjustment evidence, held-out validation, and final testing; it is distinct from model-internal patch stride hyperparameters. Timestamp boundaries may match by exact text or by equivalent parsed timestamp value; each boundary row is the last history/forecast-origin row assigned to the preceding split. Evaluation windows after a boundary may reuse earlier true rows as history context, then start evaluated targets after `forecast_gap`. Do not mix ratios and timestamps. If the current user task prompt explicitly states timestamp splitting, `forecast_gap`, or `stride`/`window_stride`, the tool will conservatively recover those fields before freezing instead of silently accepting a mismatched ratio/default contract. The task automatically fixes the front 50% of the resulting validation split as optional generative prediction reasoning evidence and keeps the back 50% as held-out validation evaluation; models and scalers train on the full resulting training split. On success, freezes all parameters into `.forecast/task.json`. Immediately afterward, call `forecast_prediction_prior ask_start`; the phase machine will not enter `pre-forecast` until the user has submitted or declined a prediction-prior dataset. Returns an error if `task.json` already exists. Call this before any experiment can run.
