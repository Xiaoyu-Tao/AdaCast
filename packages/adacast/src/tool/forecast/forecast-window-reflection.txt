Configure and run AdaCast's window-level reflection and test skill-reasoning controller.

Use `configure` exactly once during Planner after pre-forecast analysis and before entering Forecast. It derives a training baseline, calibrates moderate target-scale constraints from the reserved validation-front half, and freezes the result without accessing validation-back or test targets. Use `run_validation` once in Forecast for each final per-family validation-back baseline after any generative prediction reasoning decision is locked. Use `run_test` once in Critic only for the globally selected test model, after its optional locked skill has been applied or skipped. The test run must reuse the exact model artifact from the matching validation run. `read` returns the durable reflection state.

For every Critic prediction window requiring reasoning, preparation creates hash-bound evidence candidates and a raw-prior initial state. An isolated seeker dynamically chooses at most one unused experience, context, or knowledge candidate that addresses the current `needed_evidence`; there is no fixed candidate order. Isolated ExperienceReasoner, ContextReasoner, and KnowledgeReasoner components generate complete prediction proposals without state mutation authority. ExperienceReasoner receives the current state and a hash-bound reference showing how the locked rules act on the immutable initial prediction; the reference is not a state transition and is never mechanically applied to the current prediction. Frozen transition checks validate the generated prediction, the gap assessor evaluates the proposed prediction against all candidates, and only then does a separate reducer atomically commit predictions, appended evidence, `evidence_gap`, and `needed_evidence` to a content-addressed state. The Evidence Loop's terminal committed prediction is the final window result. Finalization verifies only its structure, state artifact hash, evidence provenance, and leakage boundary; it does not run a post-loop semantic safety repair.

For every test Critic execution, every prediction window enters this loop. Raw test windows and skill-guided windows without a matching experience rule still receive context and knowledge candidates; experience is present only when a locked rule matches. Use `status` with `run_id`, `status_split`, and the same candidate id to inspect exact completed, pending, not-started, and partially committed window states. Use `resume_test` with the original test and validation ids to continue only a matching interrupted checkpoint. Loop phase, attempted candidates, traces, and the current content-addressed state are persisted per window.

Every actual isolated LLM invocation is also persisted per window under the reflection correction audit tree, including retries and failures. Each call artifact records the exact request, system prompt, provider-returned visible text, parsed structured result, public rationale when present, error, child session id, and sequence number. The audit records visible model output only; hidden provider chain-of-thought is unavailable and is never reconstructed.

Validation behavior remains independent from skill acceptance: one hard violation or two distinct soft warnings trigger isolated blind repair, and validation-back remains the whole-metric acceptance gate. Every test window uses exact visible history, model predictions through the forecast gap and target horizon, and deterministic sample/exogenous features. A matching accepted skill additionally contributes an experience candidate and deterministic anchor. Normal Evidence Loop termination includes evidence sufficiency, candidate exhaustion, and an `unpredictable` decision. Those terminal states are final. A predictable, non-exhausted provider/schema/empty/truncated failure remains resumable and is reopened at the Evidence Loop checkpoint instead of being reused as fallback.
