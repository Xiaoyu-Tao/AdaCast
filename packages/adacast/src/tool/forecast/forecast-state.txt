Manage forecasting experiment state and phase transitions. Supports these subcommands:

- `read`: Read the current enriched experiment context. Returns a structured JSON object with: current_best (run_id, model, metrics), per_family_best (object keyed by model family — "statistical", "deep_learning", "foundation", or "unclassified" — each with run_id, model, metrics for the best-performing experiment in that family by MSE), recent_failures (last 5 crash/discard entries with run_id, model, failure_reason, decision), budget (remaining, total, consecutive_no_improvement, consecutive_crashes), expert_feedback (most recent entry with text and timestamp, or null), auto_mode (enabled, active_agent, state, pause_reason, auto_approve_permissions, auto_approve_skills, handoffs), and python_dir. Lazily freezes budget thresholds from CAST.md on first call during forecast phase.
- `append`: Record a completed experiment in `history.jsonl` only when another tool has not already persisted it. Existing run IDs are ignored. `generate_model` writes its own terminal ExperimentRecord, so do not append those results manually.
- `best`: Read or update the current best result stored in `best.json`.
- `resume`: Rebuild state from `history.jsonl` after an interruption and return completed run IDs, current best result, budget consumed, and experiment count.
- `budget`: Read or update budget tracking in `budget.json`.
- `init`: Initialize the `.forecast/` directory structure (skills/, runs/, reports/, viz/), create STATE.md, and register `.forecast/skills` in adacast.json for skill scanner discovery.
- `transition`: Transition to the next phase. Requires `target_phase`. Validates preconditions: init->pre-forecast (`task.json` exists and `forecast_prediction_prior ask_start` has recorded the user's submit/decline choice), pre-forecast->skills-review (reports/pre-forecast.md exists), skills-review->forecast (skills_confirmed is true), forecast->post-forecast (requires `forecast_adjustment_decision ask_start` in Manual mode or `auto_start` in Auto Mode to record disabled, lightweight prediction reasoning, or deep prediction reasoning first; if adjustment is enabled, also requires a locked active adjustment skill or no-effective-skill record). The skills-review transition also generates `.forecast/CONTEXT.md` containing CAST.md constraints and pre-forecast structured conclusions. The post-forecast transition makes a best-effort attempt to publish the current final `.forecast/skills/` to global Forecast memory, creates `reports/historical-explanations.md` alongside the final report placeholder, and queues compaction so the Critic handoff is rebuilt from `.forecast/` artifacts. Memory publish failure is recorded in STATE.md but does not block the phase transition.
- `phase_gate`: Assert the current phase matches `target_phase`. Returns ok or throws PhaseGateError.
- `confirm_skills`: Mark the skill set as confirmed during the skills-review phase. Must be in skills-review phase.
- `configure_auto_mode`: Persist Auto Mode state inside `.forecast/STATE.md`. Pass `auto_mode_update` with any subset of: enabled, active_agent, state (`clarifying`, `skills-review`, `running`, `handoff`, `waiting`, `paused`), pause_reason, auto_approve_permissions, auto_approve_skills, `handoff` (append one audit record), and `reset_handoffs`.
- `check_reflection`: Verify that the most recent experiment in `history.jsonl` has a paired ReflectionRecord before the next round proceeds.
- `update_stop_counters`: After each experiment attempt, pass `stop_counter_input: { run_id, improvement, crashed }` to update consecutive_no_improvement and consecutive_crashes counters. The tool counts unique deterministic run IDs for the experiment budget, but processes every audited `(run_id, attempt_index)` execution when updating crash/no-improvement counters. It catches up missed attempts and treats repeated updates for the same latest attempt as idempotent. Returns `{ stop, reason, hitl_triggered, counters: { consecutive_no_improvement, consecutive_crashes, experiments_remaining } }`. Budget exhaustion and crash threshold terminate immediately. Outside Auto Mode, the no-improvement threshold triggers HITL; in Auto Mode it remains unpaused so the Forecaster can automatically reflect, decide whether to run generative prediction reasoning, and hand off. Only `crash` status increments the crash counter (not ipc_error or timeout).
- `record_expert_feedback`: Record domain expert guidance in `history.jsonl` as an expert_feedback entry. Pass `expert_feedback_text` with the expert's guidance. Resets consecutive_no_improvement counter to 0 so the experiment loop can continue after HITL.

Strict phase protocol: call `forecast_state read` when unsure, then advance only one legal edge at a time: `init` -> `pre-forecast` -> `skills-review` -> `forecast` -> `post-forecast`. If a downstream artifact already exists but the state is still `init`, transition to `pre-forecast` first; do not jump to `skills-review` or call `confirm_skills`.

All state files live in the `.forecast/` directory. Auto Mode durability also lives in `.forecast/STATE.md`, so the workflow has one authoritative source of truth. Use this tool instead of direct file reads or writes for experiment state management. Do not manually edit `.forecast/STATE.md`; use `transition`, `confirm_skills`, or `configure_auto_mode`.
